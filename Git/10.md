GitHub Pages へデプロイする設定のまとめです。教材の手順と、あなたの hashimoto-19.github.io のやり方をあわせて整理します。

全体の流れ
コードを書く
→ GitHub に push
→ GitHub Actions がビルド
→ GitHub Pages が公開
→ https://ユーザー名.github.io/ で見られる
React（Vite）は静的ファイル（dist/）にしてから公開します。その自動化が GitHub Actions です。

1. リポジトリを用意する
   種類 リポジトリ名 URL 例
   個人サイト
   ユーザー名.github.io
   https://hashimoto-19.github.io/
   プロジェクトサイト
   任意の名前
   https://ユーザー名.github.io/リポジトリ名/
   あなたは 個人サイト（hashimoto-19.github.io）です。

2. vite.config.js に base を設定
   個人サイト（ユーザー名.github.io）の場合：

import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
export default defineConfig({
base: "/",
plugins: [react()],
});
プロジェクトサイト（教材の書き方）の場合：

export default defineConfig({
base: process.env.GITHUB_PAGES ? "/REPOSITORY_NAME/" : "./",
plugins: [react()],
});
REPOSITORY_NAME は実際のリポジトリ名に置き換えます。
※ 個人サイトでは base: "/" で OK です。

3. GitHub Actions のワークフローを作る
   ファイル例: .github/workflows/deploy.yml（教材だと deploy-gh-pages.yml）

やること:

checkout（コード取得）
Node セットアップ
npm ci
npm run build → dist/ ができる
dist/ を Pages にアップロード
デプロイ
必要な権限:

permissions:
contents: read
pages: write
id-token: write
main に push すると自動実行されます。

4. GitHub 上で Pages を有効化
   リポジトリ → Settings
   左メニュー Pages
   Build and deployment の Source を GitHub Actions にする
   （教材どおり。Deploy from a branch ではなく GitHub Actions が正しい）

5. push する
   git add .
   git commit -m "GitHub Pagesへデプロイする設定を追加"
   git push -u origin main
   その後:

Actions タブでワークフローが成功したか確認
https://ユーザー名.github.io/ にアクセス
反映されないときは数分待つ / Cmd+Shift+R でリロード 6. 画像が出ないとき（補足）
public の画像が本番で切れる場合は、本番用のベース URL を定数にして付けます。

export const BASE_URL =
import.meta.env.MODE === "production"
? "https://hashimoto-19.github.io"
: "";
個人サイトで /images/xxx.jpg のようにルート絶対パスなら、多くの場合そのままで動きます。
